*ft.txt*               ft.nvim — Neovim integration for the `ft` CLI

==============================================================================
INTRODUCTION                                    *ft*

ft.nvim is a Neovim plugin that integrates your Obsidian vault with Neovim
using the `ft` CLI (`ft`(1)) for link resolution and fuzzy search.

Features:
  - Follow `[[Wikilinks]]` under the cursor to the target note or heading
  - Same-file anchors: `[[#heading]]` jumps within the current buffer
  - Handles aliases: `[[Target|Display]]` and anchors: `[[Target#heading]]`
  - Autocompletion: note titles auto-complete when typing `[[`
  - Task operations: create, create subtasks, mark done, cancel, and
    edit due dates from inside nvim
  - Quote protected sections: `gz` / `:FtQuote` — quote a line range as
    a pinned `[!ft-source]` callout and paste it into any other note
    (requires ft >= 0.1.5)
  - Export clean markdown: `gy` / `:FtExport` — export a line range (or
    the whole note) as portable CommonMark, frontmatter and wikilinks
    stripped, for pasting outside the vault (requires ft >= 0.1.5)

Note: `![[embeds]]` inline rendering is no longer supported — it was
removed in the architecture v2 rework; the plugin is not a Markdown
renderer (see `ARCHITECTURE.md`). Legacy `embeds` config keys are
silently ignored.

Requires: Neovim >= 0.9, `ft` CLI installed on PATH.

==============================================================================
INSTALLATION                                    *ft-install*

Using lazy.nvim:

>lua
  {
    'path/to/ft.nvim',                  -- or a git remote
    lazy = true,
    ft = 'markdown',                     -- load for markdown files
    config = function()
      require('ft').setup({
        -- vault = '/path/to/your/vault',   -- optional: explicit path
        follow = { keymap = 'gf' },
        completion = { enable = true },
      })
    end,
  }
<

==============================================================================
FOLLOW WIKILINKS                                *ft-follow*

:PREF FtFollow                                  *:FtFollow*

  Follow the `[[Wikilink]]` under the cursor. Opens the target note in
  the current window. Supports:
  - `[[Target]]`         →   open the note
  - `[[Target|Alias]]`   →   open the note (alias ignored)
  - `[[Target#Anchor]]`  →   open the note and jump to the heading
  - `[[#Anchor]]`        →   jump to heading in the current buffer

  Resolution uses `ft find` under the hood, so fuzzy matching applies:
  `[[finance]]` will find `Areas/finance.md` even if the exact title
  doesn't match.

Keymap:                                       *ft-follow-keymap*

  Default keymap is `gf` (normal mode). Works only on wikilinks;
  when the cursor is not on a wikilink, shows an info message.

  To use a different key:

>lua
  require('ft').setup({
    follow = { keymap = '<leader>wf' },
  })
<

TASK OPERATIONS                                  *ft-tasks*

Create, mark done, cancel, and edit due dates of tasks from inside
nvim. All task serialization and date logic lives in the `ft` CLI
(`ft tasks`); the plugin only turns the cursor position and your input
into argv, then reloads the buffer.

Commands:                                      *ft-tasks-commands*

:FtTaskCreate                                  *:FtTaskCreate*

  Create a task at the cursor line (existing content is pushed down).
  Prompts for the description via |vim.ui.input|; when the current
  line has text, the prompt is pre-filled with it, so confirming
  "turns the current line into a task". After success the buffer is
  reloaded and the cursor lands on the new task.

  Inline due dates (same syntax as the ft TUI quickline): a `due:`
  token is extracted and passed to `ft tasks create --due`, which
  resolves relative / keyword / ISO dates into the task line's ISO
  date. No need to type ISO dates yourself:

    Buy milk due:+2d      due in two days
    Call dentist due:today
    Review due:next monday

  Escape with a backslash to keep the text literal: `\due:tomorrow`.
  A repeated or empty `due:` aborts with an error. Duplicates are
  allowed (ft's `--force` is always passed).

:FtTaskSubtask                                 *:FtTaskSubtask*

  Create a subtask under the task at the cursor line (ft's
  `tasks create --parent`). The new task is indented to match the
  parent's existing children, or two spaces past the parent when it
  has none, and lands after the parent's whole block — nesting is
  natural, so invoking again on the new subtask goes one level
  deeper. The parent is captured when the command is invoked: moving
  the cursor while the prompt is open does not retarget it.

  The prompt starts empty (the current line is the parent, not a
  draft). Inline `due:` dates work exactly as in |:FtTaskCreate|.
  Duplicates are allowed. After success the buffer reloads and the
  cursor stays on the parent's line, so repeating the command adds
  sibling subtasks. A line that is not a task shows ft's warning.

:FtTaskDone                                     *:FtTaskDone*

  Mark the task under the cursor done (`ft tasks complete` with the
  exact `<file>:<line>` selector). Recurring tasks get their next
  instance written. Completing an already-done task is a no-op with
  an info message, not an error. A line that is not a task shows ft's
  warning.

:FtTaskCancel                                  *:FtTaskCancel*

  Cancel the task under the cursor (`ft tasks cancel`). Cancelling an
  already-cancelled task is a no-op (ft treats it as success).

:FtTaskDue                                      *:FtTaskDue*

  Set or clear the due date of the task under the cursor
  (`ft tasks edit --due`). Prompts for the date; ft's date syntax
  applies — `+2d`, `today`, `next monday`, or an ISO date. Enter
  `none` to clear the due date. An empty prompt cancels (nothing
  changes).

All operations save the buffer to disk before running ft, and
reload it afterwards — undo history is preserved (the mutation is one
undoable step). The note-index cache is marked dirty so completion
stays fresh.

Keymaps:                                        *ft-tasks-keymaps*

  Default keymaps (per markdown buffer inside a vault):

    <leader>tt   create a task at the cursor line
    <leader>ts   create a subtask under the task at the cursor line
    <leader>td   mark the task under the cursor done
    <leader>tc   cancel the task under the cursor
    <leader>te   set/clear the due date of the task under the cursor

  To change or disable them:

>lua
  require('ft').setup({
    tasks = {
      keymaps = {
        create = '<leader>tn',
        subtask = '<leader>tn2',
        done = false,       -- disable: no keymap, command still works
        cancel = '<leader>tx',
        due = '<leader>tdue',
      },
    },
  })
<

QUOTE (PROTECTED SECTIONS)                          *ft-quote*

  Quote a line range of the current note as a protected section — the
  canonical `[!ft-source]` callout `ft notes quote` emits, pinned to
  HEAD (requires ft >= 0.1.5). The callout lands in your registers;
  paste it into any other note.

Usage:                                            *ft-quote-usage*

  `gz` is a true operator: press it, then a motion or text object.

    gzap     quote the paragraph under the cursor
    gz3j     quote the cursor line plus three lines down
    gzgG     quote from the cursor to the end of the note
    gz       (visual mode) quote the selection

  `:FtQuote` quotes the current line in normal mode and the selection
  in visual mode (it also accepts an explicit range, e.g.
  `:3,6FtQuote`). After the operator the cursor returns to the start of
  the range, so repeating `gz` plus a motion grows the quote.

Registers:                                        *ft-quote-registers*

  On success the callout is placed linewise into:

    "   unnamed register — plain `p` pastes the section
    f   named register — a stable home, only ever written by ft.nvim;
        shared with export (last op wins)
    +   system clipboard — survives closing nvim and reopening

  With `clipboard=unnamedplus` the unnamed register and the clipboard
  are the same register, so `p` in a fresh session pastes the section.
  A clipboard that cannot be written is skipped silently; the success
  notification lists the registers that were actually set. Any of the
  three can be disabled under `quote.registers`.

  A failed quote (e.g. an uncommitted source) writes nothing — your
  previous quote stays in the registers.

Save-before-quote:                                *ft-quote-save*

  The buffer is saved to disk before quoting, so the pinned lines match
  what you see (same pattern as the task operations).

Prerequisites:                                    *ft-quote-prereqs*

  `ft notes quote` pins to HEAD: the source note must be committed and
  unmodified. A note with uncommitted changes — anywhere in the file;
  the clean check is whole-file, not per-range — shows a warning with
  ft's commit-or-stash hint; the plugin never touches git. The vault
  must be a git repository.

Pasting into a synth note:                        *ft-quote-synth*

  A pasted section is plain markdown and renders in any note. To have
  it checked by `ft notes synth verify`, the destination note needs
  `ft.synth.enabled: true` in its frontmatter — synth notes created via
  `ft notes synth scaffold` carry it automatically.

Keymaps:                                          *ft-quote-keymaps*

  Default: `gz` (normal-mode operator + visual-mode key) in every
  markdown buffer inside a vault. To change or disable:

>lua
  require('ft').setup({
    quote = {
      keymaps = { operator = '<leader>fq' }, -- or false to disable
      registers = { named = false },         -- drop the `f` register
    },
  })

EXPORT (CLEAN COMMONMARK)                           *ft-export*

  Export a line range of the current note as clean, portable markdown:
  frontmatter, `[!ft-source]` callout headers, and wikilinks stripped
  by `ft notes export` (requires ft >= 0.1.5). The result lands in
  your registers; paste it into any other app, chat, or note without
  the vault provenance. The inverse of quoting (`gz` wraps a range into
  a pinned callout; `gy` strips it back out for external targets).

Usage:                                            *ft-export-usage*

  `gy` is a true operator: press it, then a motion or text object.

    gyap     export the paragraph under the cursor
    gy3j     export the cursor line plus three lines down
    gyG      export from the cursor to the end of the note
    gy       (visual mode) export the selection

  `:FtExport` exports the whole note in normal mode and the selection
  in visual mode (it also accepts an explicit range, e.g.
  `:3,6FtExport`). After the operator the cursor returns to the start
  of the range, so repeating `gy` plus a motion grows the export.

Registers:                                        *ft-export-registers*

  On success the exported text is placed linewise into:

    "   unnamed register — plain `p` pastes the block
    f   named register — a stable home, only ever written by ft.nvim;
        shared with quote (last op wins)
    +   system clipboard — survives closing nvim and reopening

  With `clipboard=unnamedplus` the unnamed register and the clipboard
  are the same register, so `p` in a fresh session pastes the block.
  A clipboard that cannot be written is skipped silently; the success
  notification lists the registers that were actually set. Any of the
  three can be disabled under `export.registers`.

  A failed export writes nothing — your previous quote/export stays in
  the registers.

What gets stripped:                             *ft-export-stripping*

  `ft notes export` renders the working tree as clean CommonMark:

    - frontmatter is never exported (a range starting inside it is
      clamped to the first body line)
    - `[!ft-source]` callout headers are dropped; their `> body` lines
      survive as ordinary blockquotes
    - `[[wikilinks]]` become plain text (the display text when present),
      `![[embeds]]` become CommonMark images

  Code blocks are content, not vault structure — nothing inside a
  fenced or indented code block is converted or dropped. No git is
  involved: unlike quote, export does not require committed files.

Empty export:                                     *ft-export-empty*

  A range fully inside the frontmatter exports nothing (ft exits 0 with
  empty output) — that is success, not an error. The plugin reports it
  at INFO and leaves the registers untouched.

Save-before-export:                              *ft-export-save*

  The buffer is saved to disk before exporting, so the exported text
  matches what you see (same pattern as quote and the task
  operations).

Keymaps:                                          *ft-export-keymaps*

  Default: `gy` (normal-mode operator + visual-mode key) in every
  markdown buffer inside a vault. To change or disable:

>lua
  require('ft').setup({
    export = {
      keymaps = { operator = '<leader>fe' }, -- or false to disable
      registers = { named = false },         -- drop the `f` register
    },
  })

AUTOCOMPLETION                                  *ft-completion*

  When typing `[[`, note titles from your vault appear in the
  completion menu. Typing more narrows the list.

Integration:                                  *ft-completion-integration*

  **blink.cmp** (default in LazyVim) — automatically registered.
  No config changes needed.

  **No framework** — falls back to `'omnifunc'` with `<C-x><C-o>`.
  Auto-triggers after typing `[[` (works with auto-pair plugins).

Cache:                                        *ft-completion-cache*

  The note list is fetched from `ft graph query` (async) and cached.
  The cache is derived, never authoritative: it is marked dirty by
  vault events (`BufWritePost` / `BufDelete` / `BufNewFile` on `.md`
  files inside the vault) and rebuilt lazily, single-flight, with a
  monotonic generation counter. Use
  `:lua require("ft.cache").refresh()` to force a rebuild.

  To disable:

>lua
  require('ft').setup({
    completion = { enable = false },
  })
<

==============================================================================
VAULT DISCOVERY                                  *ft-vault-discovery*

The vault root is discovered in this order (highest precedence first):

1. `FT_VAULT` environment variable
2. The `vault` option passed to `require('ft').setup({ vault = '...' })`
3. Walking up from the current buffer's directory for `.obsidian/`
4. Walking up from the current working directory for `.obsidian/`

If no vault is found, all features show an error message.

==============================================================================
REQUIREMENTS                                    *ft-requirements*

- Neovim >= 0.9 (uses `vim.json`, `vim.pesc`, `vim.keymap.set`, `vim.fn.jobstart`)
- The `ft` CLI tool (build from `ft` repo):
  Install with `cargo install --path ft` from the `ft` repository.
  Must be on `$PATH`.
  Quoting protected sections requires ft >= 0.1.5.
