*ft.txt*               ft.nvim — Neovim integration for the `ft` CLI

==============================================================================
INTRODUCTION                                    *ft*

ft.nvim is a Neovim plugin that integrates your Obsidian vault with Neovim
using the `ft` CLI (`ft`(1)) for link resolution and fuzzy search.

Features:
  - Follow `[[Wikilinks]]` under the cursor to the target note or heading
  - Same-file anchors: `[[#heading]]` jumps within the current buffer
  - Handles aliases: `[[Target|Display]]` and anchors: `[[Target#heading]]`
  - Autocompletion: note titles auto-complete when typing `[[`
  - Embed rendering: `![[linked note]]` content shown inline in normal mode

Requires: Neovim >= 0.9, `ft` CLI installed on PATH.

==============================================================================
INSTALLATION                                    *ft-install*

Using lazy.nvim:

>lua
  {
    'path/to/ft.nvim',                  -- or a git remote
    lazy = true,
    ft = 'markdown',                     -- load for markdown files
    config = function()
      require('ft').setup({
        -- vault = '/path/to/your/vault',   -- optional: explicit path
        follow = { keymap = 'gf' },
        completion = { enable = true },
        embeds   = { enable = true },
      })
    end,
  }
<

==============================================================================
FOLLOW WIKILINKS                                *ft-follow*

:PREF FtFollow                                  *:FtFollow*

  Follow the `[[Wikilink]]` under the cursor. Opens the target note in
  the current window. Supports:
  - `[[Target]]`         →   open the note
  - `[[Target|Alias]]`   →   open the note (alias ignored)
  - `[[Target#Anchor]]`  →   open the note and jump to the heading
  - `[[#Anchor]]`        →   jump to heading in the current buffer

  Resolution uses `ft find` under the hood, so fuzzy matching applies:
  `[[finance]]` will find `Areas/finance.md` even if the exact title
  doesn't match.

Keymap:                                       *ft-follow-keymap*

  Default keymap is `gf` (normal mode). Works only on wikilinks;
  when the cursor is not on a wikilink, shows an info message.

  To use a different key:

>lua
  require('ft').setup({
    follow = { keymap = '<leader>wf' },
  })
<

==============================================================================
AUTOCOMPLETION                                  *ft-completion*

  When typing `[[`, note titles from your vault appear in the
  completion menu. Typing more narrows the list.

Integration:                                  *ft-completion-integration*

  **blink.cmp** (default in LazyVim) — automatically registered.
  No config changes needed.

  **No framework** — falls back to `'omnifunc'` with `<C-x><C-o>`.
  Auto-triggers after typing `[[` (works with auto-pair plugins).

Cache:                                        *ft-completion-cache*

  The note list is fetched from `ft graph query` once per session.
  Use `:lua require("ft.cache").refresh()` to rebuild it manually.

  To disable:

>lua
  require('ft').setup({
    completion = { enable = false },
  })
<

==============================================================================
EMBED RENDERING                                 *ft-embed*

  In normal mode, when the cursor rests on a line containing
  `![[linked note]]`, the target note's content is rendered as
  virtual text lines below the current line.

  Layout::

    Some text ![[Meeting Notes]]                   ← the source line
    ────────────────────────────────────────      ← separator (Comment hl)
    # Meeting Notes                                ← rendered content
    ## Attendees
    - Alice
    - Bob
    ────────────────────────────────────────      ← closing separator

  The separators use the `Comment` highlight group (typically
  dimmed/gray) so embedded content is visually distinct from the
  real buffer.

Behaviour:                                    *ft-embed-behaviour*

  - Triggers on `CursorHold` (approx. 400ms after the cursor stops
    moving in normal mode).
  - Clears when you enter insert mode, when the buffer is written,
    or when you leave the buffer.
  - Caches note content by file mtime so repeated lookups of the
    same note are fast.
  - Truncates long notes at 50 lines by default.
  - Unresolved targets (notes that don't exist yet) show a
    placeholder.

Configuration:

  Set via global variables on the `vim` object:

>lua
  vim.g.ft_embed_max_lines = 50     -- max lines to show per embed
<

  To disable entirely:

>lua
  require('ft').setup({
    embeds = { enable = false },
  })
<

==============================================================================
VAULT DISCOVERY                                  *ft-vault-discovery*

The vault root is discovered in this order (highest precedence first):

1. `FT_VAULT` environment variable
2. The `vault` option passed to `require('ft').setup({ vault = '...' })`
3. Walking up from the current buffer's directory for `.obsidian/`
4. Walking up from the current working directory for `.obsidian/`

If no vault is found, all features show an error message.

==============================================================================
REQUIREMENTS                                    *ft-requirements*

- Neovim >= 0.9 (uses `vim.system`, `vim.json`, `vim.loop`, `vim.pesc`)
- The `ft` CLI tool (build from `ft` repo):
  Install with `cargo install --path ft` from the `ft` repository.
  Must be on `$PATH`.
